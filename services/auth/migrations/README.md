# Схема auth_db

`00001_auth_init.sql` — начальная goose-миграция. Создаёт пустые таблицы
без загрузки учётных записей.

| Таблица | Назначение |
|---|---|
| `organizations` | UUID, уникальный ИНН, публичное название организации. |
| `users` | Email, имя, Argon2id-хеш, роль, организация, `can_submit`, активность. |
| `refresh_tokens` | SHA-256 refresh-токена, пользователь, срок действия и время отзыва. |

Email уникален без учёта регистра. `CLIENT` обязательно связан с организацией;
`ANALYST` и `ADMIN` не имеют организации и права `can_submit`.
Связи с `client_db` и `bank_db` поддерживаются UUID, без межбазовых FK.
Финансовые профили и заявки в auth не хранятся.

Пароли хранятся в PHC-формате `$argon2id$v=19$m=...,t=...,p=...$salt$hash`:
16-байтовая соль и 32-байтовый результат, Base64 без padding.
Вычисление и проверка паролей в login появятся на следующем этапе.

Refresh-токен представлен только 32-байтовым хешем. Хеш уникален, срок не больше
семи дней от создания; отзыв не может предшествовать созданию. При refresh срок
не продлевается, токен не ротируется. Отзыв выполняется через `revoked_at`.

Из корня репозитория с заполненной `.env` и запущенным PostgreSQL:

```sh
make auth-db-up
make auth-db-status
```

`make auth-db-down` удаляет эти три таблицы с их данными; это команда для
осознанного отката локальной БД. Миграция не затрагивает остальные сервисы.

Проверка ограничений и цикла Up → Down → Up:

```sh
make auth-db-test
```

Тесты создают и удаляют собственную схему в `AUTH_DATABASE_URL`. Для отдельной
тестовой БД можно запустить их напрямую с `AUTH_TEST_DATABASE_URL`:

```sh
AUTH_TEST_DATABASE_URL='postgres://user:password@127.0.0.1:5432/test_db?sslmode=disable' \
  go test -count=1 ./services/auth/migrations
```

Без этой переменной SQL-тесты пропускаются. Тестовые записи создаются
только в изолированных схемах и удаляются после проверки.
