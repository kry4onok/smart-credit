# Схема bank_db

Начальная goose-миграция: `00001_bank_init.sql`. Она создаёт только структуру,
без продуктов, пользователей и тестовых заявок. `00002_scoring_attempts.sql`
добавляет попытки scoring и отдельную версию входных данных.
`00003_catalog_publication.sql` хранит версию опубликованного каталога и
запрещает несколько активных версий одного `products.id`.

| Группа | Таблицы | Назначение |
|---|---|---|
| Каталог | `products`, `product_rules`, `catalog_publication` | Версии продуктов и правил; состояние публикации полного активного каталога. |
| Дела | `cases`, `enrichment_results`, `scoring_attempts`, `score_results` | Снимок заявки, текущий статус и история ответов внешних проверок/ML. |
| Решения | `decisions`, `info_requests`, `offers`, `audit_log` | Ручные и автоматические решения, запросы данных, оферты и аудит. |
| Доставка | `outbox`, `processed_events`, `idempotency_keys` | Атомарная публикация, защита от повтора Kafka и HTTP-команд. |

`cases.current_scoring_attempt_id` указывает на текущую попытку с той же
`scoring_input_revision`. Начало новой попытки сразу скрывает прежний score;
изменение исходных данных должно повышать revision и сбрасывать указатель в
одной транзакции. Завершение старой попытки сохраняется в истории, но не
становится текущим. Только актуальная оценка `ASSESSED` добавляется в
`score_results`; остальные доменные ответы и технические ошибки хранятся в
`scoring_attempts`. Старые demo-строки `score_results` без attempt_id видны
только до первой попытки или смены revision. Видимые изменения scoring
повышают `cases.version`, чтобы ETag карточки менялся.

`cases.id` равен `application_id` из `client.events`. Идентификаторы
организации, клиента и аналитика не имеют внешних ключей: ими владеют другие БД.
Для исходного `cases.product_id` тоже нет FK: событие с неизвестным продуктом
должно остаться доступным для ручного разбора. Оферта, напротив, может ссылаться
только на известную версию продукта.

Денежные поля — целые копейки, ставки — basis points, время — `timestamptz`.
Снимки исходных данных хранятся в `jsonb`, а поля очереди и поиска вынесены в
колонки с индексами. `score_results` проверяет соответствие score и grade
границам из ТЗ. `outbox.payload` содержит полный сериализованный protobuf
`Event`; relay публикует эти байты без реконструкции события.

Приём `client.events` должен менять дело, добавлять запись аудита и
`processed_events` в одной транзакции. Переход банка, публикуемый клиенту,
должен в той же транзакции создавать строку `outbox`. Offset Kafka
подтверждается только после commit.
