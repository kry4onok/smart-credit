## Корректность

- Полный Python suite: **179 passed**. Проверены границы grades, узлы и точное
  ROUND_HALF_UP, независимый Fraction oracle, монотонность, масштабирование денежных
  значений, независимость от UUID/legacy-полей и внешнего Decimal context.
- Проверены отсутствие/явный ноль, структурные ошибки, неприменимость и порядок
  валидации. Вклады восстанавливают score, причины имеют верный знак и порядок.
- Реальные gRPC tests: health, статусы, deadlines, одновременные запросы,
  лимит сообщения, безопасные логи, сокрытие INTERNAL details, остановка SIGTERM,
  отказ при ошибочном конфиге до открытия порта.
- Все существующие Go-тесты выполнены командой `go test ./...`; ошибок нет.
- `generate_proto.py --check`: совпадение всех generated Go/Python файлов.
- Ruff check и format проверяются с `ml/scoring/pyproject.toml`.
- Docker image собран; health сообщает SERVING. Python и Go → Python smoke
  против контейнера: **10/10 + 10/10**.

Результаты оцениваемых personas: **938/A, 700/B, 510/C, 472/D, 55/E,
975/A, 0/E**. Последний результат содержит score с explicit presence.

## Локальные измерения

Условия: macOS arm64, Python 3.12.12; CPU, без GPU, БД и внешнего модельного API.
Один профиль `risk_a`, 10 запросов прогрева, 200 измеренных запросов,
конкурентность 10, RPC deadline 2 с. Перцентили nearest-rank,
время наблюдается клиентом. Результаты относятся к конкретному короткому прогону.

| Среда сервера | p50 | p95 | p99 | max | Запросов/с |
|---|---:|---:|---:|---:|---:|
| Локальный Python, localhost | 1.833 мс | 2.270 мс | 2.447 мс | 2.603 мс | 5047.19 |
| Linux arm64 в Docker Desktop, порт localhost | 3.341 мс | 6.442 мс | 8.069 мс | 10.163 мс | 2566.87 |

Моментальный RSS локального Python-процесса после нагрузки: **30 MiB** (`ps`,
30720 KiB), не пиковый RSS. Docker stats в отдельном снимке: **37.89 MiB / 256 MiB**,
это метрика памяти контейнера, не RSS Python. Compose ограничивает scoring одним CPU
и 256 MiB. Эти снимки не являются длительным нагрузочным тестом или production SLO.

Повторить: `make scoring-up scoring-evaluate`, затем при необходимости
`docker stats --no-stream` для конкретного контейнера scoring. Клиентский JSON
оставляет `server_rss_bytes=null`: он не может измерять память удалённого сервера.

## Границы подтверждённого результата

Synthetic fixtures и property tests подтверждают соответствие формуле и контракту.
Они **не измеряют** качество прогноза дефолта: реальной размеченной выборки нет,
ROC-AUC, PR-AUC и калибровка PD не заявляются. Выбор модели и путь дальнейшего
развития описаны в [model card](SCORING_MODEL_CARD.md).

Go smoke проверяет generated Go client → настоящий Python gRPC-сервис.
Банковский Kafka-конвейер, запись оценки в БД, защита revision/attempt и клиентское
решение этим прогоном не проверены. Они остаются совместной интеграцией backend
по [соглашению](SCORING_BACKEND_AGREEMENT.md). GitHub workflow добавлен;
его удалённый запуск проверяется отдельно и не приравнивается к локальным тестам.
