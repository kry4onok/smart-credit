# ML assistant

`SummarizeCase` составляет короткое резюме для аналитика. `ExplainDecision` формирует уведомление клиенту по уже принятому банком решению. Ассистент не принимает решение и не меняет скоринг.

## Новый метод Help

Python-сервис поддерживает `smartcredit.assistant.v2.AssistantHelpService.Help` после появления сгенерированных `help_pb2`/`help_pb2_grpc` от backend-интеграции. Старые методы остаются доступными. Для `Help` задайте `ASSISTANT_CATALOG_PATH` с путём к согласованному каталогу. Если каталог отсутствует или версия в запросе не совпадает, сервис возвращает `FAILED_PRECONDITION` и причину `UNSUPPORTED_CATALOG_VERSION` в trailing metadata `assistant-error`.

Пока утверждённый каталог и полные fixtures не переданы, `ml/assistant/tests/fixtures/test-catalog.json` служит только для локальных тестов. Его версия `assistant-test-v0` не является банковской версией `assistant-text-v1`. Прямой gRPC smoke: `PYTHONPATH=proto/gen/python ml/assistant/.venv/bin/python scripts/assistant_help_smoke.py --target 127.0.0.1:50052 --expect-source template`. Для него сервер должен быть запущен с тестовым каталогом. Тесты нового метода автоматически пропускаются до появления generated-классов; после их поставки пропусков быть не должно.

## Запуск через Docker Compose

Ollama запускается на компьютере отдельно от Docker. Установите [Ollama](https://ollama.com/download), запустите приложение или `ollama serve` и загрузите модель:

```bash
ollama pull qwen2.5:7b
ollama list
```

Из корня репозитория запустите assistant и проверьте оба метода:

```bash
cp .env.example .env  # только при первом запуске
make assistant-up
make assistant-smoke
```

Сервис слушает `assistant:50052` в сети Compose и `127.0.0.1:50052` на компьютере. Контейнер обращается к Ollama по `http://host.docker.internal:11434`. Для других адресов и модели задайте `OLLAMA_URL`, `OLLAMA_MODEL` и `ASSISTANT_PORT` в `.env`. На Docker Desktop для Mac `host.docker.internal` указывает на компьютер; при запуске в другой среде проверьте доступ к Ollama из контейнера.

`make assistant-smoke` проверяет **все семь** сценариев из `services/bank-service/seeds/demo.sql`: семь резюме и два объяснения по реально заданным решениям №3 и №4. Снимок входных полей для прямого gRPC-прогона лежит в `ml/assistant/scenarios.json` и включает статус, цель, проверенные описания причин и правил. Скрипт проверяет обязательные поля в тексте и `model_version` каждого ответа. Для проверки качества генерации команда даёт каждому вызову до 30 секунд. Это **не** проверка банковского дедлайна 5 секунд. `template` означает fallback внутри assistant. Для остановки используйте `make assistant-down`, для просмотра логов — `make assistant-logs`.

## Настройка модели для проверки экспертами

Настройки читаются при старте assistant; после изменения `.env` пересоздайте контейнер через `make assistant-up`.

| Переменная | Значение |
|---|---|
| `LLM_PROVIDER` | `ollama` (по умолчанию) или `openai` для совместимого `/v1/chat/completions` API. |
| `LLM_BASE_URL` | Базовый URL сервера модели. Для Ollama это адрес до `/api/generate`; для OpenAI-совместимого сервера — адрес с `/v1`, без `/chat/completions`. |
| `LLM_MODEL` | Имя установленной или доступной модели. |
| `LLM_API_KEY` | Необязательный Bearer-ключ, который отправляется серверу модели. Для локальной Ollama оставьте пустым. |

Пустые `LLM_BASE_URL` и `LLM_MODEL` берутся из прежних `OLLAMA_URL` и `OLLAMA_MODEL`; старый способ запуска работает. Пример своего локального Ollama: `LLM_PROVIDER=ollama`, `LLM_BASE_URL=http://host.docker.internal:11434`, `LLM_MODEL=qwen2.5:3b`, пустой `LLM_API_KEY`. Для OpenAI-совместимого локального сервера укажите `LLM_PROVIDER=openai`, `LLM_BASE_URL=http://host.docker.internal:8001/v1`, его модель и ключ, если нужен. Сервер должен поддерживать `response_format: {"type":"json_object"}`. Значение `LLM_API_KEY` храните только в локальном `.env`, не коммитьте. При обращении к удалённой модели используйте HTTPS и не передавайте туда реальные банковские данные без разрешения команды.

Ollama можно запустить у эксперта на его машине; постоянно держать вашу Ollama в интернете не требуется. Для проверки без любой модели используйте fallback-команду ниже. Основной кредитный конвейер работает и без assistant через шаблон bank-service.

## Локальный запуск без Docker

Нужны Python 3.12 и запущенная [Ollama](https://ollama.com/download) с моделью `qwen2.5:3b`. Ollama работает вне Docker. Из корня репозитория создайте окружение и установите зависимости из `pyproject.toml`:

```bash
python3.12 -m venv ml/assistant/.venv
ml/assistant/.venv/bin/python -m pip install 'grpcio==1.78.0' 'protobuf==6.33.5'
ollama pull qwen2.5:3b
PYTHONPATH=proto/gen/python OLLAMA_MODEL=qwen2.5:3b ml/assistant/.venv/bin/python ml/assistant/server.py
```

Если окружение уже создано, первую команду можно пропустить. Адрес gRPC по умолчанию — `127.0.0.1:50052`; адрес Ollama — `http://127.0.0.1:11434`. Их можно изменить через `ASSISTANT_ADDR` и `OLLAMA_URL`.

Для ручной проверки обоих методов можно использовать `grpcui -plaintext -proto proto/assistant/assistant.proto 127.0.0.1:50052`. Если ассистент запускается локально без Docker, `LLM_BASE_URL` для Ollama обычно `http://127.0.0.1:11434`.

## Контракт с bank-service

`bank-service` вызывает оба метода gRPC-сервиса. Его target в Compose: `assistant:50052`; адрес передаётся через `BANK_ASSISTANT_GRPC_ADDR`. `ExplainDecision` вызывается при ручном `APPROVE`, `COUNTER` и `REJECT` после предварительной проверки дела и оферты, до транзакции сохранения решения. Контракт определён в `proto/assistant/assistant.proto`.

| Метод | Что передаёт bank-service | Что использует assistant |
|---|---|---|
| `SummarizeCase` | `application_id`, продукт, код и описание цели, код и описание статуса, grade, коды и описания причин скоринга и правил банка | Модель получает только утверждённые описания, если они есть; для неизвестного кода получает только сам код. Описание причины берётся из сохранённого результата скоринга конкретного дела. `application_id` в текст не попадает. Старые поля кодов сохранены для совместимости. |
| `ExplainDecision` | `application_id`, выбранный аналитиком `outcome`, название исходного продукта заявки, безопасный `analyst_public_reason`; для `APPROVE`/`COUNTER` — проверенные банком название предложенного продукта, сумму в копейках, срок в месяцах и ставку в базисных пунктах | Исход решения, продукт заявки, публичную причину и точные условия выбранной оферты. `application_id` в текст не попадает. Коды причин банк сейчас не передаёт. |

Аналитик вводит публичную причину; банк проверяет её наличие и длину до вызова `ExplainDecision`. Если клиенту нужно сообщить конкретную причину, её следует передать готовой фразой в `analyst_public_reason`. Внутренний `comment` аналитика, сырые персональные данные и внутренние причины скоринга передавать в клиентское объяснение нельзя. Для резюме аналитика банк сопоставляет статусы, цели и известные правила со своими описаниями; неизвестный код не получает придуманной расшифровки. Демокод `REVIEW_REQUIRED` означает только необходимость ручного разбора, без конкретной причины.

Backend выставляет `source=assistant`, когда получен текст с версией модели; `model_version=template` отображает как `source=template`. При ошибке gRPC или истечении дедлайна backend формирует собственный шаблон и также ставит `source=template`. Дедлайн вызова из bank-service по умолчанию — 5 секунд. Для демо на компьютере с медленной моделью можно задать `BANK_ASSISTANT_TIMEOUT=20s` в `.env` и пересоздать bank-service; значение должно быть меньше `BANK_HTTP_WRITE_TIMEOUT` (по умолчанию 30 секунд). При отсутствии модели ожидание fallback тогда тоже может занять до 20 секунд. Вызов assistant не меняет score, решение или оферту. HTTP-метод резюме подключён. При ручном решении банк сохраняет ответ `ExplainDecision` в `public_reason`, а для оферты — также в `offer.explanation`, и публикует существующее клиентское событие. При недоступности ассистента банк сохраняет исходную публичную причину; для `APPROVE` без причины использует короткий шаблон. `REQUEST_INFO` оставляет исходное сообщение запроса документов. Название предложенного продукта, сумма, срок и ставка передаются только после предварительной проверки оферты банком. Ассистент выводит их из полей запроса без выдумывания условий.

## Ограничение фактов и fallback

Модель отвечает в JSON-формате с температурой `0`. Для резюме аналитика сервис передаёт модели короткий список утверждённых русских описаний; машинные коды используются только когда описания нет. Промпт перечисляет только реально присутствующие поля. Сервис проверяет, что ответ содержит их дословно и не добавляет известных опасных утверждений, включая грейд без скоринга. Если проверка не проходит или модель недоступна, сервис возвращает резюме из тех же проверенных описаний с `model_version=template`. Текст модели может совпасть с шаблоном; происхождение показывает `model_version` или HTTP-поле `source`. Эвристическая проверка не доказывает отсутствие любых вымышленных фраз: тексты с `model_version` модели нужно прочитать глазами.

Для клиентского текста модель выбирает только тон (`neutral` или `empathetic`). Статус, публичная причина и проверенные условия выбранной оферты подставляются программой из запроса; внутренние коды без расшифровки не публикуются. При ошибке модели используется нейтральный шаблон с `model_version=template`. Backend учитывает этот маркер для резюме; если gRPC-сервис недоступен или истёк дедлайн, fallback резюме остаётся на стороне bank-service.

## Проверка качества текста

1. Выполните `make assistant-smoke`. Для каждого номера проверьте, что в квадратных скобках стоит имя модели. `template` значит, что модель не дала принятый ответ; смотрите `make assistant-logs`. Чтобы отдельно проверить банковский дедлайн, запустите `PYTHONPATH=proto/gen/python ml/assistant/.venv/bin/python scripts/assistant_smoke.py --timeout 5 --expect-version qwen2.5:7b` при запущенном assistant. На тестовом Mac Qwen2.5:3b прошла все девять вызовов с дедлайном 30 секунд; резюме дел №1, №2 и №4 в контейнере занимали 6,6–7,7 секунды. Поэтому для показа текста модели через bank-service на этом компьютере нужен `BANK_ASSISTANT_TIMEOUT=20s`. На другом оборудовании результат может отличаться.
2. Прочитайте все девять строк. В №1, №2 и №4 должны быть переданные грейд, статус, цель и утверждённые описания причин и правил без выдуманных расшифровок. В №3 и №5–7 грейда, причин и правил скоринга быть не должно. В №3 клиенту можно сообщать только о выписке; в №4 — только о встречном предложении с переданной публичной причиной. В тексте №4 должны быть «Гибкий кредит», 4 000 000 ₽, 24 мес. и 18,50%; других условий, решений или обещаний быть не должно.
3. При `template` проверьте, что основной сценарий остаётся понятным и безопасным. Для принудительной проверки задайте недоступный `OLLAMA_URL` (и пустой `LLM_BASE_URL`), пересоздайте assistant, затем запустите скрипт с `--expect-version template`.

Прямой скрипт не читает базу и не заменяет банковский E2E. Снимок семи дел основан на seed SQL; если сиды изменятся, обновите `scenarios.json`. Для резюме вызовите банковский HTTP `POST /backoffice/applications/{id}/summary`. Для клиентского объяснения примите решение по новому делу через `POST /backoffice/applications/{id}/decision`, затем проверьте `public_reason` и `offer.explanation` через `GET /client/applications/{id}`. Уже заполненное в seed дело №4 этот путь не запускает.

Тесты без Ollama:

```bash
PYTHONDONTWRITEBYTECODE=1 ml/assistant/.venv/bin/python -m unittest discover -s ml/assistant/tests -v
```

В контейнерном smoke используются снимки семи банковских demo-сценариев. Проверка fallback без остановки Ollama:

```bash
OLLAMA_URL=http://host.docker.internal:1 docker compose --env-file .env -f deploy/docker-compose.yml up -d --force-recreate --no-build --wait assistant
docker compose --env-file .env -f deploy/docker-compose.yml exec -T assistant .venv/bin/python /app/scripts/assistant_smoke.py --expect-version template
make assistant-up  # восстановить обычный адрес Ollama
```

Если выключен сам контейнер assistant, шаблон резюме формирует bank-service.

CI `.github/workflows/assistant.yml` запускает unit-тесты и проверяет оба метода контейнера при недоступной Ollama. Для проверки реальных ответов модели запустите `make assistant-smoke` на компьютере с установленной Ollama.
