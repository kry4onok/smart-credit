# Документы для жюри Smart Credit

Все вложения синтетические. ИНН взяты из текущего демо-каталога как ключи моков;
совпадения с реальными организациями не означают, что данные относятся к ним.
Файлы не предназначены для реальных банков, ФНС или внешних реестров.

Комплект на **26 октября 2026 года**: выписки за **01.10.2025–30.09.2026**,
годовые документы за **2025 год**, действующий патент за **2026 год**.
Даты фиксированы для воспроизводимости. Для другого месяца комплект нужно перегенерировать.

## Быстрый старт

1. Выберите демо-компанию и войдите её учётной записью. Пароли в комплект не входят.
2. В папке компании `bank_statement.txt` — выписка в формате существующего парсера.
   Остальные документы представлены парой PDF/TXT: загрузите **один** вариант.
3. Загружайте файл только в соответствующий слот продукта или активного запроса банка.
   В политике v2 все документы заранее прикладывать не требуется: источники могут закрыть требования.
4. Для ИП на ПСН после запроса банка используйте **[patent.pdf](02_ip_patent/patent.pdf)**.
   Загрузка — первый шаг; затем нажмите кнопку отправки ответа на запрос.
5. `requirement_id` берите из **текущего** плана/запроса, тип — из `accepted_document_types`.
   Примеры в `manifest.json` не заменяют ID текущей заявки. Даты покрытия должны соответствовать
   файлу и охватывать весь период требования. Патент покрывает весь 2026 год, запрос проверяет дату заявки.

## Девять основных сценариев

| Папка | Учётная запись | Что проверять |
|---|---|---|
| `01_llc_approval` | `client@smart-credit.test` | ООО: расчёт, подтверждение аналитиком, принятие и демо-подписание |
| `02_ip_patent` | `ip@smart-credit.test` | ИП: NEEDS_INFO по патенту, отправка ответа, возврат аналитику |
| `03_llc_liquidation` | `closing@smart-credit.test` | Отказ по допуску; загрузка финансовых документов не снимает ликвидацию |
| `04_llc_grade_b` | `warehouse@smart-credit.test` | Категория B; сравнение условий с пекарней |
| `05_llc_counteroffer` | `workshop@smart-credit.test` | Запрос 5 млн на 12 месяцев, альтернативная сумма/срок |
| `06_llc_cash_gap` | `cashgap@smart-credit.test` | Высокий балл, но нет посильного варианта в стрессе |
| `07_llc_loss` | `loss@smart-credit.test` | Убыточный поток, концентрация и просрочка; отказ по скоркарте |
| `08_llc_manual_review` | `review@smart-credit.test` | Ручной разбор и ограничения на выдачу оферты |
| `09_llc_source_unavailable` | `service@smart-credit.test` | Бюро не ответило; неизвестное не приравнивается к нулю |

Это **ожидаемое поведение из кода**, а не подтверждение live E2E. Для учётных записей
нужен актуальный dev seed; наличие файлов не создаёт пользователей и не обновляет развёрнутый стенд.
Источники: `pkg/demodata/companies.json`, `pkg/assessment/demo.go`,
`pkg/requirements/build.go`, `scripts/assessment_docker_smoke.py`.

## Что находится внутри

- `bank_statement.txt` — годовая выписка с отдельными операциями, остатками и оборотами.
- `management_report.pdf/txt` — месячные потоки, отдельная управленческая прибыль, долг и допущения.
- `accounting_report.pdf/txt` — для ООО: учебный баланс и отчёт о результатах за предыдущий календарный год.
- `receivables_payables.pdf/txt` — для ООО: торговая дебиторская/кредиторская задолженность на дату запроса.
- `tax_declaration_usn_*.pdf/txt` — годовое подтверждение доходов по УСН.
- `tax_declaration_3ndfl_osno.pdf/txt` — для расширенного ИП на ОСНО.
- `income_ledger_*.pdf/txt` — для ИП: отдельные книги по каждому режиму и периоду.
- `patent.pdf/txt` — для ИП с ПСН.
- `business_plan.pdf/txt` — для продукта/запроса, явно допускающего `BUSINESS_PLAN`.
  Политика v2 сама это требование не создаёт; не пытайтесь загрузить его в другой слот.
- `profile.json` — пример данных профиля для текущего варианта; не файл для загрузки в слот документа.
  Прибыль намеренно отсутствует, как в web demoProfile. Значение из управленческого макета
  можно ввести вручную, только когда это действительно запрошено. Отсутствие не равно нулю.
- `scenario.json` — параметры сценария, явно заданные модельные суммы и 24-месячный график долга.
- `manifest.json` — типы, периоды, примеры требований, контрольные суммы и негативные проверки.

## Расширенные варианты ИП

`extended` содержит пять комплектов на том же синтетическом ИП. Это **варианты профиля**,
а не пять новых компаний и не пять автоматически созданных аккаунтов.
Используйте изолированный демо-стенд, обновите профиль и создайте новую заявку:
существующая заявка содержит свой снимок компании. `profile.json` показывает нужную историю режимов.

| Папка | Особенность |
|---|---|
| `ip_usn_income` | УСН «доходы», декларация и книга |
| `ip_usn_expense` | УСН «доходы минус расходы», декларация и книга |
| `ip_osno` | ОСНО, 3-НДФЛ и книга |
| `ip_usn_psn` | УСН+ПСН одновременно; по модели 50% оборота на каждый режим, две книги |
| `ip_regime_changed` | УСН до 31.12.2025, ПСН с 01.01.2026; две книги без пересечения периодов |

Полный каталог профилей с отсутствующим/нулевым/отрицательным результатом, неизвестной
формой, АУСН, противоречивой историей налогов и устаревшим долгом уже находится в
`seed/profile-requirements/requirements-cases.json`. Эти проверки меняют поля профиля;
приложенный файл не исправляет невалидный профиль. Не смешивайте суммы того каталога
(контрактные сценарии) с этим комплектом, построенным по текущим девяти UI-персонам.

## Негативные проверки

| Файл/действие | Уровень и ожидаемый результат |
|---|---|
| `negative/statement_bad_totals.txt` | Парсер: `INCONSISTENT_TOTALS`. Загрузчик TXT может принять файл: он не проверяет арифметику |
| `negative/statement_wrong_period.txt` | Парсер принимает. v2 отклоняет покрытие года одним месяцем: `INVALID_DOCUMENT_COVERAGE` |
| `negative/patent_expired.txt` | При передаче дат из файла v2 возвращает `INVALID_DOCUMENT_COVERAGE` |
| `negative/invalid_signature.pdf` | Намеренно не PDF: загрузка возвращает `INVALID_DOCUMENT` |
| `negative/empty.txt` | Пустой файл: загрузка возвращает `INVALID_DOCUMENT` |
| Патент в слот выписки | Проверка типа и требования: отклонение |
| Загрузить патент, но не отправить ответ | Заявка не считается ответившей на запрос банка |

Сервер сверяет **переданные метаданные покрытия**, а не даты внутри PDF/TXT.
Для проверки просроченного патента укажите даты прошлого года через API; если UI
автоматически подставляет текущий период, этот тест через UI не доказывает проверку содержимого.
Не выдавайте приём файла за проверку его подлинности или финансового содержания.

## Факты реализации и допущения макетов

**По коду:** загрузка поддерживает PDF/TXT до 5 MiB; парсер понимает специальную TXT-выписку.
Парсер существует отдельно и не подключён к автоматическому чтению загружаемых файлов.
Текущая оценка получает поток от DemoSources. PDF, книги и декларации не изменяют
скоринг автоматически. Статусы зависят также от источников, продукта и действий аналитика.

**Допущения документов:** поток повторяется по месяцам; налоговый платёж — компонент
демо-модели, не расчёт по законодательству; выплаты собственнику уменьшают денежный поток,
но не управленческую прибыль. Годовая отчётность за 2025 год моделируется отдельно
с теми же месячными суммами. Макеты деклараций не воспроизводят официальные бланки,
не рассчитывают налоги и не содержат поддельных печатей или подписей.

Для убыточного сценария в выписке отдельно указан вклад учредителя 100 000 ₽:
иначе при исходных 500 000 ₽ и годовом потоке −600 000 ₽ возник бы отрицательный остаток.
Вклад не считается выручкой и **не добавлен во встроенный источник оценки**.

## Воспроизведение и хранение в Git

Генератор: `scripts/generate_jury_documents.py`. Нужен Python с `reportlab`
и TTF-шрифт с кириллицей. Пример из корня репозитория:

```sh
python3 scripts/generate_jury_documents.py --as-of 2026-10-26
# На Linux передайте --font и --bold-font с путями к DejaVu Sans или другому TTF.
```

Для новой даты меняются периоды файлов и manifest; эта памятка описывает исходный выпуск.
Для альтернативного выпуска используйте `--output /путь/к/новому-комплекту`.
Контрольные суммы положительных вложений перечислены в `manifest.json`.
Новые файлы разрешены точечными исключениями в `.gitignore`; коммит и push не выполняются генератором.
Снимок текущего `pkg/demodata/companies.json` должен публиковаться вместе с соответствующими
изменениями приложения: в рабочей копии он может ещё не быть закоммичен.
