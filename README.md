# Smart Credit

**Демо кредитования малого бизнеса.** Клиент подаёт заявку от имени компании; банк проверяет данные и правила продукта, а положительное решение утверждает аналитик. В браузере можно пройти путь от заявки и оферты до демо-подписи и статуса выдачи. `scoring` оценивает риск, а `assistant` формулирует текст — сами они кредит не одобряют.

## Быстрый старт для жюри

### 1. Подготовьте компьютер

- Установите и запустите **Docker** с плагином **Docker Compose v2** (Docker Desktop на macOS/Windows, Docker Engine с Compose на Linux). Выделите Docker не меньше 4 CPU и 8 ГБ памяти. На Windows команды ниже выполняйте в WSL2. Если Ollama работает на том же компьютере, ориентируйтесь на 16 ГБ общей памяти и более.
- Установите **`make`** и **Go** с поддержкой toolchain `1.27.1` из [go.mod](go.mod). Makefile использует Go для миграций и создания демо-учёток. При первом запуске понадобятся интернет и время на образы, модули Go и сборку контейнеров. Node.js и Python отдельно устанавливать не нужно.
- Проверьте `docker compose version`, `go version` и `make --version`. Убедитесь, что доступны порты стенда: `3000` (web), `8000` (Swagger/API), `8080`, `8081`, `8082`, `8083`, `5432`, `9092`, `50051`–`50053`. Их публикация задана в [Compose](deploy/docker-compose.yml); если порт занят, освободите его или измените соответствующую настройку.

### 2. Создайте локальный `.env`

```bash
cp .env.example .env
```

В `.env` замените три **демонстрационных** пароля из примера на значения для показа:

```dotenv
AUTH_DEV_CLIENT_PASSWORD=client
AUTH_DEV_ADMIN_PASSWORD=admin
AUTH_DEV_ANALYST_PASSWORD=analyst
```

Остальные значения из `.env.example` подходят для локального стенда. `.env` игнорируется Git; не добавляйте его в коммит. Учётные записи создаёт команда запуска:

| Роль | Логин | Пароль |
|---|---|---|
| Клиент | `client@smart-credit.test` | `client` |
| Клиент, ИП | `ip@smart-credit.test` | `client` |
| Клиент, отказ | `closing@smart-credit.test` | `client` |
| Администратор | `admin@smart-credit.test` | `admin` |
| Аналитик | `analyst@smart-credit.test` | `analyst` |

### 3. Установите и проверьте Ollama

**Ollama** — отдельная программа для запуска модели `Qwen2.5:7b`. Контейнер `assistant` обращается к её HTTP API и составляет подсказки клиенту, резюме дела и объяснения. **Кредитное решение, сумма и ставка определяются банковскими правилами и аналитиком, не моделью.** Если Ollama недоступна, проект показывает проверенный шаблон и кредитный сценарий продолжается.

Если Ollama уже работает на отдельном сервере, установку на компьютере жюри пропустите и укажите адрес сервера в `OLLAMA_URL` ниже. На Windows команды Ollama выполняйте в PowerShell, а `make demo-up` — в WSL2. Для локального показа:

1. **Установите программу.** На macOS или Windows скачайте установщик с [официальной страницы Ollama](https://ollama.com/download), установите и откройте приложение. На Linux выполните [официальную команду установки](https://docs.ollama.com/linux):

   ```bash
   curl -fsSL https://ollama.com/install.sh | sh
   ```

2. **Запустите сервер Ollama.** На macOS/Windows достаточно открытого приложения. При ручном запуске используйте `ollama serve` в отдельном терминале; если сервер уже запущен, второй экземпляр запускать не нужно. На Linux при установленной службе можно выполнить `sudo systemctl start ollama`. Проверьте, что локальный API отвечает:

   ```bash
   ollama --version
   curl -fsS http://localhost:11434/api/tags
   ```

   Второй вызов должен вернуть JSON с полем `models` (список может быть пуст до загрузки модели). В PowerShell вместо `curl -fsS ...` используйте `Invoke-RestMethod http://localhost:11434/api/tags`.

3. **Загрузите и запустите именно 7B.** Для первого скачивания нужен интернет и около 4,7 ГБ свободного места под [тег модели](https://ollama.com/library/qwen2.5%3A7b):

   ```bash
   ollama pull qwen2.5:7b
   ollama list
   ollama run qwen2.5:7b "Ответь одним словом: готово"
   ```

   В списке должен появиться `qwen2.5:7b`, а последняя команда должна вернуть текстовый ответ. Так проверяется сама модель **до** запуска Smart Credit. Веса не входят в Docker-образы и не скачиваются командой `make demo-up`.

4. **Проверьте подключение проекта.** В `.env` оставьте `OLLAMA_MODEL=qwen2.5:7b` и для Ollama на этом компьютере `OLLAMA_URL=http://host.docker.internal:11434`. Compose добавляет `host.docker.internal` для контейнера `assistant`. На Linux с Docker Engine Ollama по умолчанию слушает только `127.0.0.1`: для доступа контейнера настройте адрес прослушивания через [`OLLAMA_HOST`](https://docs.ollama.com/faq#how-can-i-expose-ollama-on-my-network), например `0.0.0.0:11434` для локального доверенного стенда. Для службы Ollama задайте `Environment="OLLAMA_HOST=0.0.0.0:11434"` через `sudo systemctl edit ollama.service`, затем выполните `sudo systemctl daemon-reload` и `sudo systemctl restart ollama`. Для уже развёрнутой Ollama замените URL на адрес, доступный **из контейнера**, и убедитесь, что на сервере загружен тот же тег. Оставьте `LLM_MODEL` пустым, чтобы использовался `OLLAMA_MODEL`. Если ответы 7B не успевают за банковским таймаутом, задайте в `.env` перед запуском `BANK_ASSISTANT_TIMEOUT=20s` (резюме дела) и `ASSISTANT_HELP_TIMEOUT=25s` (помощник в карточке). Больше 25 секунд локально не ставьте: nginx и HTTP-серверы сервисов ждут ответа 30 секунд. Скорость зависит от оборудования.

После `make demo-up` выполните `make assistant-smoke`: он проверяет вызовы `assistant` через gRPC. В успешном выводе ожидается версия `qwen2.5:7b`; `template` означает, что модель не ответила вовремя или текст не прошёл проверку. Тогда посмотрите `make assistant-logs`, `ollama list` и `OLLAMA_URL`. Дополнительная диагностика — в [README assistant](ml/assistant/README.md).

### 4. Запустите демо одной командой

```bash
make demo-up
```

Команда поднимает инфраструктуру, сервисы, `web` и Swagger, применяет миграции и загружает демо-учётки и данные банка. Откройте [кабинет клиента](http://localhost:3000/cabinet), [рабочее место банка](http://localhost:3000/bank) или [Swagger](http://localhost:8000/docs/). Адреса соответствуют портам по умолчанию из `.env.example`.

**Показать полный путь** (так же он проходит на публичном стенде):

1. **Клиент.** Войдите как `client@smart-credit.test`. Заполните профиль компании с ИНН `7707083893` (при первом сохранении ИНН фиксируется; на публичном стенде профиль уже заполнен).
2. В «Подобрать кредит» выберите цель «Товар и текущие расходы» и продукт «Кредит по денежному потоку» (`SME_CASHFLOW_V2`). В черновике укажите **5 000 000 ₽ / 12 месяцев**, а в блоке «Если всю сумму дать не получится» — «Минимальная сумма, которая решит задачу» **1 000 000 ₽**. Без минимальной суммы банк не уменьшает запрос и при нехватке денежного потока ответит, что подходящих условий нет. Черновик сохраняется автоматически; нажмите «Отправить заявку».
3. Через несколько секунд банк проверит данные и источники и рассчитает до трёх вариантов. Варианты до подтверждения аналитиком **не являются офертами**.
4. **Аналитик.** Войдите как `analyst@smart-credit.test` в `/bank`, откройте дело, нажмите «Взять в работу», затем «Предложить этот вариант». Заполните обязательный «Внутренний комментарий» и «Причину для клиента» (её увидит клиент) и нажмите «Зафиксировать решение». Если сумма меньше запрошенной, это контрпредложение.
5. **Клиент.** В карточке статус «Есть предложение»: нажмите «Принять предложение», дождитесь «Оформления», отметьте «Подтверждаю выбранные условия кредита», нажмите «Подписать договор» и дождитесь статуса «Деньги выданы» (внутренний `DISBURSED`).

Другие исходы: `ip@smart-credit.test` (ИП на патенте) — банк запросит только патент, после загрузки патента и отправки ответа на запрос дело вернётся аналитику; `closing@smart-credit.test` (ликвидируемая компания) — автоматический отказ. Для демо-документов подойдёт любой текстовый `.txt`: банк проверяет наличие файла, значения из него не извлекаются. Поля и альтернативные клиентские исходы — в [README client-service](services/client-service/README.md), действия аналитика и банковские статусы — в [README bank-service](services/bank-service/README.md).

Ollama остаётся отдельным процессом: `make infra-down` останавливает Compose-стенд, но не Ollama. Источник ответа не показывается пользователю: для проверки работы модели выполните шаг 3 и посмотрите `make assistant-logs`.

Проверить контейнеры: `make infra-ps`; посмотреть логи: `make infra-logs`; остановить стенд с сохранением томов: `make infra-down`; удалить стенд вместе с данными (тома БД, ключ auth, документы): `make demo-reset`.

### Документы и дополнительные сценарии для показа

Готовые синтетические PDF/TXT собраны в **[demo/jury-documents](demo/jury-documents/README.md)**. Там описаны девять компаний, расширенные варианты ИП и негативные проверки; [manifest.json](demo/jury-documents/manifest.json) содержит типы документов, периоды и контрольные суммы. Комплект рассчитан на 26 октября 2026 года, выписки — за 01.10.2025–30.09.2026.

- **Запрос патента у ИП:** войдите как `ip@smart-credit.test`, создайте заявку и дождитесь запроса банка. Прикрепите [patent.pdf](demo/jury-documents/02_ip_patent/patent.pdf) в слот патента, затем нажмите отправку ответа на запрос. Одной загрузки недостаточно.
- **Выписка или финансовые документы:** используйте [комплект ООО](demo/jury-documents/01_llc_approval) либо папку выбранной компании. [bank_statement.txt](demo/jury-documents/01_llc_approval/bank_statement.txt) предназначен для выписки; другие документы представлены в PDF/TXT — достаточно одного варианта в соответствующем слоте. Не нужно прикладывать весь комплект заранее: в v2 источники могут закрыть требования без файлов.
- **Ошибки загрузки и периода:** файлы из [negative](demo/jury-documents/negative) предназначены только для отрицательных проверок. Ожидаемые результаты и различия между проверкой файла и его метаданных приведены в [памятке](demo/jury-documents/README.md#негативные-проверки).

Файлы показывают работу с документами, но не меняют скоринг автоматически: содержимое вложений не распознаётся, денежный поток берётся из синтетических источников. `profile.json`, `scenario.json` и `manifest.json` — справочные данные, их не загружают в слоты документов. Все файлы учебные и не предназначены для реальных банков или ведомств.

На экране входа выберите компанию; в пустом профиле нажмите «Подставить данные компании», в каталоге — «Подставить параметры». Используйте продукт «Кредит по денежному потоку». Дополнительные аккаунты создаются командой `make auth-dev-seed` с тем же `AUTH_DEV_CLIENT_PASSWORD`; обновление файлов само по себе не создаёт пользователей на уже работающем сервере.

| Учётная запись | Сценарий |
|---|---|
| `warehouse@smart-credit.test` | Категория B: сравнение ставки и доступных условий |
| `workshop@smart-credit.test` | Альтернативная сумма или срок для запроса 5 млн ₽; минимум 1 млн ₽ разрешает уменьшение суммы |
| `cashgap@smart-credit.test` | Высокая оценка риска, но нет посильного варианта в стрессе |
| `loss@smart-credit.test` | Убыток и просрочка: отказ после расчёта |
| `review@smart-credit.test` | Ручной разбор и ограничения на предложение условий |
| `service@smart-credit.test` | Недоступность бюро: ручная проверка без автоматического отказа |

Полный путь проверяйте на новых заявках. Семь старых банковских дел с UUID `...0001`–`...0007` служат иллюстрациями этапов; повторный seed не переписывает историю. Баллы, потоки и ожидаемые исходы привязаны к [каталогу компаний](pkg/demodata/companies.json) и параметрам запроса.

## Что реализовано и где границы MVP

Есть профиль компании, каталог продуктов с четырьмя целями финансирования (для «Несколько целей или другая цель» клиент поясняет, на что пойдут деньги), черновик с автосохранением и удалением, документы, отправка заявки, запрос недостающих данных, проверки, автоматический запрос данных или отказ и ручное подтверждение оферты, оферта и контрпредложение, принятие/отказ, отзыв, истечение срока, демо-подпись и демо-выдача. Для продукта `SME_CASHFLOW_V2` также реализована отдельная экспертная оценка денежного потока с расчётными вариантами и подтверждением аналитика ([описание v2](docs/ASSESSMENT_V2.md)). `DECISION` означает **ожидание применения банковских правил** после оценки, а не одобрение: результатом могут стать запрос данных, ручной разбор или отказ; оферту после положительной оценки подтверждает аналитик.

Бизнес-состояние между `client-service` и `bank-service` передаётся через Kafka (`client.events`, `bank.events`), без общего доступа к их БД. Техническое исключение: банк читает уже отправленный оригинал документа защищённым HTTP GET в `client-service`; этот вызов не меняет состояние заявки.

Для локального MVP бюро возвращает синтетические данные; скоркарты v1 и v2 экспертные, без статистической калибровки вероятности дефолта. Подпись и выдача симулируются: юридически значимая электронная подпись не создаётся, реальные деньги не переводятся. Интерфейс показывает пользовательский путь без технических пометок; это ограничение относится ко всем сценариям стенда. Документ проверяется по формату и сохраняется, но значения из него автоматически не извлекаются. Локальная модель для `assistant` запускается отдельно; при её отсутствии работает шаблон.

## Дальнейшее развитие MVP

**Инфраструктура интеллектуального помощника.** В текущем развёртывании Ollama выполняет модель Qwen2.5:7b на CPU сервера с ограниченными вычислительными ресурсами. Конфигурация не обеспечивает полного запаса производительности для устойчивого выполнения запросов модели в пределах установленных таймаутов, особенно при одновременных обращениях. Это может увеличивать время ответа и частоту перехода к проверенным шаблонным формулировкам. Данное ограничение относится к скорости и доступности генерации текста и не влияет на правила принятия кредитного решения. Дальнейшее развитие предусматривает размещение модели на инфраструктуре с достаточным объёмом памяти и вычислительной мощностью, оценку целесообразности GPU и нагрузочное тестирование перед выбором конфигурации.

**Развитие кредитного скоринга.** Для MVP выбран детерминированный экспертный скоринг без обученной статистической модели. Это решение позволило сосредоточить разработку на интерфейсе, понятности объяснений и удобстве прохождения кредитного сценария пользователем без специальных финансовых знаний. Текущая оценка основана на явных правилах и не является статистически откалиброванной вероятностью дефолта. Потенциальное продолжение проекта — развитие ML-компонента: формирование разрешённой исторической выборки с подтверждёнными исходами, обучение и независимая валидация моделей, калибровка риска и сравнение результатов с действующей экспертной скоркартой. Внедрение обученной модели потребует отдельной проверки качества, объяснимости и устойчивости; оно не входит в реализованный объём MVP.

Другие направления развития: подключение реальных источников проверок, извлечение данных из документов, юридически значимая электронная подпись и фактическая выдача средств. Эти возможности требуют отдельной реализации; сроки их выполнения не заданы.
